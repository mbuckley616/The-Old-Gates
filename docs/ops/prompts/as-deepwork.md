Take, in this order, ONE card that is: (a) "queued" with `start` now; (b) "queued" with `start` quiet, when the hour is 22 or later or before 7; (c) "paused"; (d) "running" with `started_at` more than five hours ago (a session that died: resume it from its branch and say so in `note`); (e) "waiting" whose question is answered: a `Michael:` line under its entry in docs/decisions.md on main or on its branch, or a `decisions` card with `fable` = the card id at status "answered" or "done". (f) "review" whose branch no longer merges cleanly onto main: after `git fetch origin`, `git merge-tree --write-tree origin/main origin/<branch>` exits non-zero, or its `merges/fable-<id>` card is "blocked" with a conflict as the reason (skip it while its `note` says `Re-merging origin/main since <time>` less than two hours ago). (g) "review" whose PR has gone red: its `merges/fable-<id>` card has `ci` "red" (or is "blocked" with failing tests as the reason), or the finished check runs on the branch head include a failure (skip it while its `note` says `Fixing red CI since <time>` less than two hours ago, and while CI on the head is still running). Nobody else fixes a finished branch, so this is yours (added 19 Oct 2026, after PR #95 sat blocked with no owner). Rule (g) is upkeep like (f): do steps 1 and 2 of Before any work and skip 3 and 4; write `note` = `Fixing red CI since <ISO>`; read the failing jobs' logs (GitHub MCP) and name each failing suite and check; run those suites here several times each (`node tests/run.mjs <name>`, at least five runs, and once under load beside another suite) and fix the cause: the game code when the test shows a real fault a player could meet (a kid wedged, a wrong count), the test when it fails only from timing or load. ## The work
Do the item as the card's `prompt` says and as CLAUDE.md's session steps go: targeted edits to index.html (LF line endings, literal Unicode in strings, new code marked `// v1.NN:`), parsecheck after every batch, verification in headless Chromium with a test in tests/ (`npm install` once; `node tests/run.mjs <name>` for one suite, `npm test` for all; drive time with `g.spin(n)`, never timeouts; `g.scenario(id)` enters any scenario; if the harness cannot run at all that is STUCK, not something to skip), `node scripts/tag.mjs bump` (one version per session), a devlog.md entry in CLAUDE.md's format (`## v1.NN — <title>`, prose with reasons and numbers, `### Verified`, `### Still open`), the backlog item marked, a commit ending `Co-Authored-By: Claude <noreply@anthropic.com>`, `git push -u origin <branch>`. A big item is several sessions back to back, each its own version, commit, devlog entry and push; write the card's `versions` (e.g. `v1.141–v1.144`) as you go. One PR from your branch to main titled `Fable: <card title>`, label `auto`, no reviewer, no assignee; one PR comment per session (what changed, what the tests showed, what needs eyes). Do not wait on CI; if CI has already reported red on your branch when you start, fixing it is a fair first session. Never invent features that are not in the card.
## Decisions are Michael's
When the design is open (the card or the backlog says so; anything touching a rule of play, prices, what a player sees on a screen, or a choice between two shapes of the same rewrite that he would see), do not guess: write the question under `## Pending` in docs/decisions.md on your branch (the question in plain words, 2–4 lettered options, your recommendation marked; screenshots under docs/prototypes/ linked raw from your branch when a picture helps), commit and push. Then set the card status "waiting" with `note` = the question in one line, and END THE RUN. The producer carries the question to Michael; a later check of yours finds the answer (the cheap check, rule e) and takes the card again. Never edit docs/design_brief.md.
## Time and stopping
Work for up to FOUR hours from `started_at`. Commit and push at every clean point. At four hours, or when the next step would take more than an hour, stop at a clean point, push, set the card status "paused" with `note` = where you stopped and what comes next, and end; your next check resumes it. If after a real effort a test will not pass, a runtime error is not understood or the merge cannot be resolved: do not push broken code; push the work in progress to `auto/wip-fable-<id>`, open an issue `STUCK: <what>` (label `stuck` if it exists) with what you tried, saw and would try next, set the card "stuck" with `note`, and end.
## Finishing
When the item is done (the devlog entries written, `npm test` green here, the PR open and pushed): set the card status "review" with `pr` = the PR number, `finished_at`, `versions`, and `summary` = one or two plain sentences on what a player will notice (or "nothing a player sees" for tooling). Do not merge anything and do not close the FREEZE issue: the producer makes the merge card, Michael approves, the producer merges, itch.io gets it, and the producer lifts the freeze. If you have the Slack tools (`mcp__Slack__slack_*`, load them with ToolSearch), end a run that did work with ONE post in #neighborhood-airsoft (C0C50EAJKRC) in CLAUDE.md's room shape (`**Fable** — <title>` / `• *Did:*` with versions / `• *Next:*` / `• *Need:*`); without them, post nothing: the producer reports for you. A run that only checked and found nothing posts nothing. Never post a question to Slack.
## Rules
One item, the card's. Never push main, never force-push, never rewrite old devlog entries, never delete tests, never write to any control-room collection but your own `fable` card. Change CLAUDE.md only where the item changes what it describes. Plain prose, reasons, numbers.
