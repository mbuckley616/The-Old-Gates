## v80 — Session 2032 — a town's house keeps its roof from boot to boot (section I, QA's S2027 item)
The look builder's run of 9 Nov (about 10:20 UTC), on `auto/look-2032`. No `FREEZE:` issue was open, and the lane's last PR (#1342) had landed.
The highest session on main and on every branch was 2031 (the bodies builder's), so this is 2032. Section I held one item for this lane, QA's
from Session 2027, so it comes before card work.

**What was wrong.** A detailed house's variant (`HOUSE_VARIANTS`: thatch or slate, framed or not, rubble, and the yard's woodpile and
barrel) is rolled in `buildingGeoHi` from a stream seeded by its size, its plain twin's colours and `_houseN`. `_houseN` counts every detailed
house built so far in the boot, so a house's roof depended on which towns had loaded before its own town. QA saw it in `lookpair`: the same
lot south of Dunmore's square was timber and slate on one boot and thatched on the next (108 houses built before it in one boot, 132 in the
other). A player who reloads, or who comes by another road, would find the same house with another roof. The churches and keeps
(`churchGeoHi`, `keepGeoHi`, `_civN`) had the same fault.

**What changed** (`js/82-world-structures.js`, two lines in `js/83-world-generator.js`). Following the co-op rule, the roll is now keyed by
place. `genSettlement` sets `HOUSE_SEED = houseSeedFor(site.id, i)` (an FNV hash of the town's id with the lot's index, the same index as the
house id `g_<site>_<i>`) before a lot's builds, and clears it after. `buildingGeoHi`, `churchGeoHi` and `keepGeoHi` take their count term
from `houseSeedStep`, which returns that key while it is set and the old running count otherwise. The counts still step, so the S1884 kit
step and `lookpair`'s own reset still work as they did. A fort's two barracks are keyed by the fort and the side (`fort_<seed>`, 0 or 1). The
only builds still on the count are the coaching inn in `87-world-quests.js`, which rolls by `Math.random` anyway.

Every town house's variant moves once with this change, because the seed is new. From now on it stays put.

### Verified (headless Chromium)
- Check script (`tests/tmp`, thrown away): two boots into Dunmore with `OG_KIT_TOWNS = false`, the second with `_houseN` and `_civN` offset
  by 37 before the world loads, as if other towns had come first. Each built house's variant, thatch, eave and vertex count were compared by
  its seed. Fixed: 127 and 108 built (load order varies), and all 95 that both boots built are alike. With the old seed put back
  (`houseSeedFor` returning null): 4 of 4 differ, among them one 5 m house that is thatched on one boot and slated on the other.
- `python3 scripts/parsecheck.py`: OK.
