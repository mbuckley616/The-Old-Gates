## v80 — Session 1998 — the market house's square no longer renames Cœur de Vie's guards and villagers (backlog I: `townbarrels`)
The look builder's second session of the run that began with Session 1997, on the same branch (`auto/look-1997`).

**What QA found.** Sunday's weekly run (42479827264, s1368) had `townbarrels` red on both tries. *Its people are the people it drew
before* read -1122094953 for Cœur de Vie (pinned -1626674452) and -626595302 for Portclare (pinned 1470735334). QA left the owner open
and named the market house (S1901–1905) as the first suspect.

**What it was.** It was the market house. A town's square has its well and a few stalls, each set at a random angle and distance from
the centre (`plan.stalls`). A stall that would fall in a plot is skipped, and a skipped stall never calls `stallGeo(r)`, which picks its
cloth and its three goods from the town's stream. S1904 laid the market house on its own plot in the square. In Cœur de Vie that plot
now covers a spot where a stall used to stand, so that stall's draws are gone. Every name drawn after it moves on: the gate guards, the
night watch and the wandering villagers. I found it by drawing Cœur de Vie on 1 Nov's code (c97ed1c, from `git archive`) and on today's,
and diffing the lists. Every keeper and resident, each on their own house, is the same. Only the eight after the Lord differ (Séamus the
guard is now Sinéad, Fionn the villager Pádraig, …). The houses are the same 149 lots plus `g_coeur_de_vie_6000`, the market's room.
Today's code reads exactly CI's hashes, so the draw is stable: it changed, it did not drift.

**The change** (`js/83-world-generator.js`). A stall that *only* the market's plot leaves out still takes its draws: `stallGeoLo(r)` is
called and the geometry thrown away. That is the same pick the old code made, so the stream after the stalls is as it was before the
market house. A stall in the church's or the keep's yard is skipped as before, with no draw (S1138, pinned then). The plot test is split
so one plot can be asked alone (`inPlotOf`); `inPlot` is the same test over all of them. The stall's high copy (`stallGeoHi`) uses the
furniture's own running counter, not the town's stream, so it is not called.

**The pins.** With the change, Cœur de Vie draws 374393723, the same as 1 Nov's code. That is still not the pin (-1626674452). Portclare
draws -626595302 on today's code and on 1 Nov's alike, so nothing since 1 Nov moved it, and that is not its pin (1470735334) either. To
rule out the suite's own library (QA's S1842 changed `g.settle` on 4 Nov), I ran 1 Nov's suite and `tests/lib` against both trees, unpacked
side by side with `git archive`. Both read 374393723 and -626595302, and both read the other three towns' pins exactly. So the two pins
were not what c97ed1c draws here either. Whatever moved them came before 1 Nov, and the claim that 1 Nov's weekly run was green on them
doesn't hold up here. I can't explain that from this checkout's shallow history. The suite now pins both towns to the draw that 1 Nov's
code and this branch share, with that reason in its comment, as S1138 and S1343 did.

(A correction to this branch's history: the change to `js/83-world-generator.js` was committed with Session 1997's devlog fix, 1636eb67,
by a `commit -a`; it is this session's.)
