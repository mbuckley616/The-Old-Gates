## v80 — Session 2111 — the two coves keep their own names: Aurenne's inlet no longer overwrites the Gatelands' sea cave (card F8)
The look builder's run of 11 Nov, started about 18:50 UTC (`auto/look-2110`). No `FREEZE:` issue was open. The newest look branch (2107)
was two hours old and its PR, #1438, had gone into conflict: the systems builder's Session 2108 landed first with the same devlog file.
The run's first session (2110) carried #1438 onto main, with its Session 2108 renumbered 2110.

While reading the smuggler's cove of Session 2105 for its stair (the next item), this turned up. The kit's `places` table registered
Aurenne's cove as `cove: aurenneCove`, and the Gatelands' smugglers' sea cave of Session 1773 already held `cove: smugglersCove` in the
same object literal. The later key wins, so on the branch `PKIT.places.cove` was Aurenne's inlet. Every Gatelands sea cave's room
(`buildKitSeaCave`, 83, which reads `T.bounds` and `T.low`), its mouth on the coast (82) and the `seacove` suite would have read the wrong
piece. S2105 never reached main (it rode #1435 and then #1438), so main was never broken. The fault would have landed with #1438.
- **The fix.** Aurenne's piece is `PKIT.places.inlet` (`js/38-kit.js`). The world's off-road kind is still `'cove'`, so no cell's
  draw, id or stream moves. It reaches its piece through `offroadPiece(kind)` (`82-world-structures.js`), which maps `'cove'` to `inlet`.
  `offroadPiece` replaces `PKIT.places[kind]` in the three places the off-road code built or shaped a piece: the draw's "built yet?" test,
  `placeOffroad` and the cut ground's shape. The wayside census still filters on `PKIT.places[k]`. That is right for both coves, since
  both names exist.
- **The check.** `wayside` +1: `PKIT.places.cove` builds a sea cave with its `bounds` and `mouth`, `PKIT.places.inlet` is the inlet with its
  `shape`, and `offroadPiece('cove')` is the inlet.
