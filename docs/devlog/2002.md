## v80 — Session 2002 — `placerooms` split in two for CI's 900 s
The weekly run of 8 Nov (42479827264, shard 7) killed both tries of `placerooms` at `run.mjs`'s 900 s cap. The suite saves in each of
six rooms (home, weapon, inn, guild_f, church, cellar), reloads and continues, and every round trip is a whole boot. On that runner a
trip took 166–196 s. Try 1 died in the fifth room (`page.reload: net::ERR_ABORTED`), try 2 in the fourth. Session 1280 had already taken
out its fixed pauses, so there is no wait left to cut: each trip is the game's own boot. Here, alone, a trip is 137–181 s, the same pace.

So the suite is split, as Session 1280 split it out of `placesave`. `placerooms` keeps home, weapon and inn. The new `placerooms2` is
five lines: it sets `globalThis.PLACEROOMS_KINDS` to guild_f, church and cellar and imports `placerooms`' body. The checks are the same
ones, one per room, with nothing loosened and no fixed time added. `tests/times.json` gives the two suites 560 and 600 s, which is what
they took here, in place of 696 for the one.

### Verified (headless Chromium)
Both on main at s1375, one after the other, alone: `placerooms` 3/3 rooms in 454 s (562 s with the boot), `placerooms2` 3/3 in 504 s
(604 s); every room continued in the same room at the same spot, and no page errors. A first try with two other suites running beside
it timed out in its first room (*Hearthwick not seen after 61 s*, then the room's 60 s wait), which was the load, not the split.

### Needs eyes
Nothing. A pull request that edits `placerooms` does not select `placerooms2` with it. The selection is pipeline, so that waits for a
pipeline PR if it is ever needed.
