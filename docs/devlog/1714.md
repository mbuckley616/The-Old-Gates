## v80 — Session 1714 — the weekly run gets a job long enough to finish, and a time table that tells the truth (QA, pipeline)
QA's order 5, owed since Session 1697. The weekly full run of 1 Nov (`check` 41305372499, main c97ed1c) had 11 of its 20 shards
cancelled at the job's 90-minute limit, and 23 of its 590 suites never ran, so the week's reds were not all known.

Why: `tests/times.json` (measured in Session 1651 from the run of 25 Oct) packed every shard to 63 minutes, and the shards took 70 to
135. Read from all 20 job logs (each suite's start to the next suite's start), the suites that finished took 1.39 times what the table
said, 0.76 to 1.66 by shard and 2.14 on shard 7. Shard 7's extra was one suite: `fpweapons` hit `run.mjs`'s 900 s cap on its first try and
passed its retry in 834 s, 29 minutes where the table counts 75 s (a row in `docs/qa/flaky.md`, the next flake item). Other suites ran far
over their row too: `markyard` 851 s (counted 60, not listed), `saveui` 1,114 (473), `kitislands` 860 (433).

What changed, in two files:
- `.github/workflows/check.yml`: the `headless` job's limit is 150 minutes on a full run (the weekly one, or check run by hand) and
  90 on a pull request as before; the retry budget follows (140 and 80). Both are expressions on `needs.plan.outputs.mode`. Twenty
  stays the most shards (`MAX_SHARDS`): more would only queue, since GitHub Free runs twenty jobs at once, and a weekly run that
  takes the runners for longer delays the PRs either way.
- `tests/times.json`: every suite that finished in that run is re-timed (547, 24 of them not listed before; a suite run twice counts
  half its two tries, as before). The suites cut or never started keep their earlier time. The full run now adds up to 1,661 minutes,
  83 a shard at twenty, which the 150-minute limit holds with a retry and a slow runner to spare.

**For every other PR:** the smoke set's six suites count 1,455 s where they counted 1,108, so a pull request's run packs into five
6-minute shards instead of four. Nothing else in a PR's run changes; its limit is still 90 minutes.
