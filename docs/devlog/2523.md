The systems builder's run of 22 Nov (10:45 UTC), on `auto/systems-2523` from origin/main. No `FREEZE:` issue was open, and the last

**The hunt.** ESLint's `no-undef` over the 46 files joined in tag order (so every file's top-level names are in scope, as in the page)
names 38 identifiers no file declares. 28 are the browser's (`window`, `localStorage`, `indexedDB`, …) and three are the vendor bundles'
(`HB`, `HC`, `THREE`). `wType`, `physResistMult`, `activePortal`, `curPortal` and `DEV_SPEED_MUL` sit behind `typeof` fallbacks that
reach a name that does exist (`wt`, `resistMult`, `currentPortal`) or a console knob, so they are harmless. Three are real:
- **`sndDiscover`**. `discover` (`83-world-generator.js`) has called `if(typeof sndDiscover==='function')sndDiscover()` since the first push,
  and no file has ever defined it (`git log -S` finds it only in that line). Every *Discovered {place}.* was silent. It is now in
  `72-audio.js`, beside the draw's voices (S2515), on the audio clock: a low open fifth, D4 and A4 struck together on triangles (peaks 0.10
  and 0.08), then the octave D5 as a bell 0.22 s later (0.09, with a 0.035 sine at D6). The peak is under half the quest chime's 0.35, since
  a discovery is far more common than a quest's turn. Only one rings in any 1.5 s (`performance.now()`), so a load, a fast travel or a jump that
  finds three places at once rings once. `DISC_SND` counts the calls and the rings, as `DRAW_SND` does for the draw.
  This is the code doing what it already said, so it asks nothing; the sound itself is a stand-in a playtest can judge.
- **`_isMenuOpen`** in `86-world-crime.js`. The helm's two mouse handlers (S1821–1822: the left button fires the ballista or the broadside,
  the right one cycles the shot) ask `typeof _isMenuOpen==='function'&&_isMenuOpen()` before taking the click. `_isMenuOpen` is declared
  inside `_enterGame` (`92-creator.js`), so it is never a global, and the guard was always false. The function is exported as
  `window.isMenuOpenNow` (S690, for the pause leaf), and the handlers now ask that. It mattered little in play: a menu releases the pointer,
  and the handlers also return when nothing holds it. But a panel opened without releasing it (the case the guard was written for) would
  fire the ballista under the panel.
- **`reconcilePointerLock`**, the third, is left as it is, and is noted below.

- **`reconcilePointerLock` never runs.** It is declared inside `_enterGame`, and the loop's `if(typeof reconcilePointerLock==='function')` in

  exported the way `isMenuOpenNow` is, with the overlay's branch dropped.
