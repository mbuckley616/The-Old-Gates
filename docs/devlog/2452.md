Every `js/` file shares one scope. A `let`, `const` or `class` declared twice is a SyntaxError, and parsecheck's concatenation catches it. Two
`function`s of one name (or a `function` and a `var`) are legal, though, and the later declaration wins in silence. CLAUDE.md says to grep
before naming one. In two days that cost three systems, each found by a hand sweep, not a suite:
- magic B's `riderTick` (64) was replaced by the road rider's (87), so no rider burned or chilled from 17 Nov (S2436);
- the road's `caravanDef` was replaced by the festival's in the same file, so every road caravan sold saffron (S2437);
- S112's weapon-class hit sounds in 68 were replaced by 72's plain `sndHitEnemy` (S2443).

`tests/topnames.test.mjs` is that sweep as a suite. It boots no browser. It reads `index.html`'s 46 `<script src="js/…">` tags in order,
parses each file with Node's bundled acorn (the same `internal/deps` route `scripts/split.py` takes), and lists every top-level `function`
and `var` name held by two declarations, with file and line. One clash is known and kept: `roadPoint` in 82 and 87, judged harmless by
S2436 (its callers read either shape). It sits in the suite's `KNOWN` table with that reason, and a third check goes red when it is gone,
so the table cannot go stale. `tests/times.json` lists it at 5 s; a suite not listed would count as 60. CLAUDE.md's line on the duplicate
`function` now names the suite, so a builder can run it before pushing (2 s).

It is not in the smoke set (`SMOKE` in `tests/lib/select.mjs`, a pipeline file), so after this PR it runs only on Sundays, or when a PR
edits it. That still catches a clash within the week. Putting it in every PR's run costs about 30 s on one shard (the install, then 2 s),
and that change waits for QA's next pipeline PR and Michael's tap.
